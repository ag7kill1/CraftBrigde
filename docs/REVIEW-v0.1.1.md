# v0.1.1 代码审查与修复记录

审查日期：2026-10-25。输入为 `Blockporter-v0.1.0-Source.zip`，SHA-256：`f2a0f4cc08bef76ca0277ffebdd02cfa5c916619e4aa650f6b10f22322c043c0`。修改前，项目文件与该包逐文件一致；原始 ZIP 保留。

本轮重点检查数据迁移、世界完整性、运行目录映射、回退、实例识别和界面任务状态。以下问题均已修复并合入 v0.1.1。

## 主要发现

| 优先级 | 原行为与影响 | v0.1.1 修复 | 主要位置 |
|---|---|---|---|
| P1 | `runtime/versions/friends/saves/Home/level.dat` 可被伪装成运行文件。在常见隔离实例映射下，能够直接替换世界数据，绕过世界副本和占用锁检查。 | 版本运行文件仅允许 `<版本>/<版本>.json` 或 `.jar`；读取、预览、导入均校验。合法隔离版本描述与客户端 JAR 仍可迁移。 | `PackageEngine.ValidatePayloadPath`、`CoreAuditTests.RuntimeWorldDisguise` |
| P1 | 运行目录选在存档、配置或历史备份内时，合法的 `libraries/` 文件也可能越过游戏数据分类边界。 | 检查映射后的实际路径，禁止进入所选实例游戏数据和 `.blockporter*` 内部目录；拒绝重名、父子文件冲突和收到的 ZIP 自身。 | `PackageEngine.ValidateDestinations` |
| P1 | 预览后另一个程序创建同名世界目录，逐文件导入可能混合两个世界；改名候选也可能与包内另一个世界重名。 | 预留包内世界名称，导入前和暂存后复核目录；世界完整暂存、校验后通过同卷目录移动整体放入目标。名称被占用则停止。 | `PlanWorlds`、`CheckWorldsUnchanged`、`Import` |
| P2 | 回退仅确认备份存在；备份被修改时会把改坏的内容恢复回去。逐文件回退也不足以保护已被再次修改的完整世界。 | 备份 SHA-256 必须匹配原文件；世界按完整文件树检查并整体回退。检测到外部变更时保留整个世界，提示手动核对。 | `Import`、`VerifyWorldContents` |
| P2 | 切换源实例后扫描失败或取消，旧扫描可能继续可导出；切换目标后可能保留上一实例的共享运行目录。 | 新扫描前清空旧结果；目标变化清除旧运行映射；导入开始后旧预览立即失效，失败后须重新预览。 | `AppForm.ClearSourceScan`、`ResetSourceInstances`、`BrowseTarget`、`ExecuteImport` |
| P2 | 父版本加载器覆盖子版本信息；显式指定但缺失的继承 JAR 未标记不完整；继承启动入口可能被误判未知。 | 最近子版本声明优先，检查显式 JAR，沿继承链查找有效入口。 | `Discovery.Inspect`、`RuntimeCollector.Collect` |
| P2 | 跨卷 `.blockporter-backup-*` 和临时 `.blockporter-*.tmp` 进入文件树，导致后续导出拒绝；手动添加可进入备份子目录。 | 扫描和手动添加统一排除工具内部前缀。 | `Scanner.AddPath`、`AddCustom` |
| P2 | 取消后的临时清理失败信息丢失；成功回退后恢复记录仍显示“写入中”。 | 清理异常包含可定位路径并与任务异常一并报告；记录明确区分“已回退”和“需手动恢复”。 | `PackageEngine.Import` |
| P2 | 手动添加目录可能重新选中已取消的文件，并漏选新加入的已知分类文件；旧任务进度可能覆盖新任务状态。 | 保留原勾选，仅选中新加入的文件；按任务编号隔离排队中的进度更新。 | `AppForm.RestoreAddedSelection`、`RunJob` |

修复后的复核还覆盖了完整世界暂存目录被插入额外文件或空目录的情况：移动前不仅校验清单内文件的哈希，还核对实际文件、目录集合并拒绝链接，防止把未校验内容一起带入。

收到的原始 ZIP 在旧版导入期间已有 Windows 文件共享锁保护。本次将冲突提前到预览阶段拒绝；没有证据表明旧版会覆盖该 ZIP。

## 性能与维护性

- 文件树勾选统计改为一次后序遍历，以 3000 个构造文件验证选择统计。
- 多世界导出先分组，避免每个世界重复遍历全部扫描文件；目录改为流式枚举，并补充取消检查。
- 世界直接从暂存目录整体移入，省去另一份完整世界复制；普通文件保留临时副本和备份替换流程。
- 全部复用或保留本地时，不再创建空任务和恢复记录。
- `build.ps1 -Test` 同时执行核心与独立 STA 界面状态测试，使用与发行程序一致的 .NET 配置。构建脚本使用 UTF-8 BOM，兼容 Windows PowerShell 中文文件名。

本轮未进行真实大型整合包的吞吐量基准测试，不提供未经测量的加速比例。

## 参考与取舍

再次查看了 [Prism Launcher 的实例导出实现](https://github.com/PrismLauncher/PrismLauncher/blob/develop/launcher/ui/dialogs/ExportInstanceDialog.cpp)。它将文件树筛选、忽略项和后台 ZIP 导出分开，适合管理已知的 Prism 实例。本工具采用按需选择、后台任务和明确排除项的思路；针对跨启动器的不同目标目录，额外处理实际落盘路径、内容比较、存档副本和回退。本轮未复制第三方代码或素材。

## 尚未覆盖

- 尚未启动真实 Minecraft 或完成联机验证；夹具里的世界和模组不是可游玩数据。
- 仍需目标启动器准备匹配的 Minecraft、加载器与 Java；没有新增自动安装、启动器配置生成或服务端转换功能。
- 正常取消和可捕获异常有回退；断电、强制结束进程后的自动恢复未实现，应保留记录和备份人工检查。
- 未进行网络共享目录、真实多磁盘设备和最大规模 25 万文件的完整实机压力测试。

ZIP 格式编号保持 `1`；v0.1.0 按标准收集器导出的正常迁移包可继续导入。伪装游戏数据的非法运行文件路径会被新版拒绝。
