# CraftBridge v0.2.0

Minecraft Java 版的 Windows 本地迁移工具。A 机按用途勾选游戏数据，导出 ZIP；由你通过微信、网盘、邮件或移动硬盘传到 B 机；B 机选择目标游戏目录，预览差异后导入。程序无需服务器，也不上传文件。

源码和本项目自绘图标使用 [MIT 许可证](LICENSE)，版权署名为 `CraftBridge contributors`。参考项目与运行环境说明见 [第三方说明](docs/THIRD_PARTY.md)。

准备发布到 GitHub 时可查看 [首次上传说明](docs/GITHUB.md)。参与贡献请阅读 [CONTRIBUTING.md](CONTRIBUTING.md)；仓库已提供自动构建测试、Issue 表单和 PR 模板。

v0.2.0 正式更名 **CraftBridge**，采用简洁的浅色界面、柔和圆角与蓝色主操作。迁移流程仍是“选择内容 → 导出 ZIP → 接收端预览 → 导入”。更新说明见 `docs/RELEASE-v0.2.0.md`。

兼容读取旧 **Blockporter v0.1.0 / v0.1.1** 正常导出的 ZIP；新版导出使用 `CraftBridge` 标识，旧版程序不识别新版标识，接收方也应使用 CraftBridge。历史 `.blockporter*` 备份和临时文件继续受到排除保护，新任务记录保存在 `.craftbridge/`。此前的安全审查记录保留在 `docs/REVIEW-v0.1.1.md`。

## 开始使用

解压发行包，双击 `CraftBridge.exe`。需要 Windows 10 / 11 和 .NET Framework 4.8。保留同目录的 `CraftBridge.exe.config`。

1. **A 机导出**：关闭对应游戏。在“导出迁移包”选择启动器所在文件夹、`.minecraft` 或某个实例目录，扫描并选择具体实例。按“联机整合包”“自己搬家”“仅搬世界”等预设勾选，也可以展开文件树手选。将 ZIP 存到游戏目录外。
2. **发送 ZIP**：通过你自己选择的渠道传输。本工具不代发邮件、不连接网盘，也不处理聊天账号。
3. **B 机导入**：关闭对应游戏，打开 ZIP，选择目标启动器和**目标实例实际使用的游戏目录**，勾选需要的分类，生成预览。确认新增、复用、替换或保留的文件后，点击导入。
4. **启动检查**：在启动器中选择对应版本、加载器及游戏目录，再启动游戏。迁移工具检查文件，不运行游戏，也不保证模组之间兼容。

## 选择哪个目标目录

| 启动器 | 目标游戏目录 |
|---|---|
| PCL / HMCL | 从该版本的设置中打开“游戏文件夹”；隔离版本通常是 `.minecraft/versions/版本名`。共享目录则是 `.minecraft`。以启动器实际设置为准。 |
| 官方启动器 | 在“安装配置 → 编辑 → 更多选项 → 游戏目录”中指定独立文件夹。请先准备对应游戏版本和加载器。 |
| Prism | 先创建并运行对应版本、相同加载器的实例，然后从实例菜单打开其 Minecraft 文件夹（可能叫 `minecraft` 或 `.minecraft`）。选择这个文件夹，而非 Prism 程序所在目录。 |
| 自定义 | 直接选择实例的游戏目录。工具按文件路径迁移，不重写启动器账号或安装配置。 |

**这个首版支持游戏数据在以上目录之间迁移；创建启动器安装配置、自动安装加载器和 Java 仍交给启动器处理。** 仅复制模组不能让纯原版直接加载模组。请同时匹配 Minecraft、Forge / Fabric / NeoForge / Quilt 的版本。

## 按需迁移

- 分类包含世界、模组、配置与脚本、资源包与光影、小地图与路径点、个人设置、截图。
- 世界以完整世界为单位选择，包含其维度、玩家数据及世界内模组数据。为避免不完整世界，部分勾选某个世界会被拒绝。
- 不认识的模组数据目录可以手动添加；工具不会推断所有第三方模组配置的含义。模组和脚本是文件复制，工具不执行它们。
- “所选版本的运行文件”是可选项：从标准版本描述及继承关系收集本地版本文件、Windows 库和对应资源对象，不复制整个共享缓存。
- Forge / NeoForge 可能有安装生成文件；Prism 管理运行环境的方式也不同。首版会提示先在目标启动器准备环境，不宣称这些环境能完全离线重建。Java 运行时、启动器本体不打包。
- 服务器进程、插件数据库和跨服务端核心转换不属于此版的功能。当前主要服务于单人世界开放联机、朋友同步客户端环境和换电脑。

## 导入与恢复

- 比较文件内容的 SHA-256，不仅比较文件名。相同内容复用本地文件；缺失文件新增；不同内容按预览中选择的策略保留或备份替换。
- 同名世界内容不同，会导入为带“迁移 时间”后缀的新世界，保留原世界，避免混合两个世界的区块数据。世界先在临时目录准备并校验完整文件树，再整体移入；若预览后目标名称被占用，会停止并要求重新预览。
- B 机原本额外的模组、存档及未选数据不会自动删除。
- 需要写入的文件先在目标目录下的 `.craftbridge/tasks/` 暂存并校验，再执行写入。全部复用或保留本地时，不创建临时目录和备份。取消或失败会尝试回退已写入文件；原始 ZIP 保留。
- 替换前的文件及恢复记录保存在 `.craftbridge/backups/任务号/`。跨磁盘运行文件的备份可能保存在对应文件旁的 `.craftbridge-backup-任务号/`，恢复记录包含位置。回退前核对备份内容；已安装文件或世界被其他程序更改时保留现状并提示手动核对。恢复记录区分成功、已回退和需手动恢复，备份与临时文件分开，不自动删除备份。
- 成功、失败或取消后清理本次临时解包目录；如果文件被其他程序占用，会显示清理位置。断电或强制结束进程后，请保留恢复记录及备份，先检查状态。
- 预览后目标或 ZIP 发生变化会要求重新预览。读取到世界锁时会要求关闭对应游戏。运行文件禁止映射进所选实例的存档、模组、配置和工具备份目录。
- 迁移包拒绝越界路径、符号链接、重名路径和未列出的内容。文件数量上限 25 万，总解压体积上限 2 TB。ZIP 校验用于完整性检查，不代表包内模组的来源可信。

首版在 B 机收到包后对比文件，减少重复解压和写入。A 机按用途筛选缩小 ZIP；尚未实现 B 机清单回传、打包前精确差异筛选、分卷或断点续传。

## 从源码构建与测试

无需安装 NuGet 依赖或 .NET SDK，使用 Windows 自带的 .NET Framework C# 编译器：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Test
```

输出为 `dist/CraftBridge.exe`，核心测试结果为 `build/test-results.json`，界面状态测试结果为 `build/ui-test-results.json`。测试使用独立构造数据，不访问真实 Minecraft 存档；测试夹具中的世界和模组不可直接游玩。

## 设计参考

参考了 [Prism Launcher](https://github.com/PrismLauncher/PrismLauncher) 的实例管理和 ZIP 导出思路，以及 [SaveState](https://github.com/Matteo842/SaveState) 的本地备份恢复流程。此版本为独立实现，没有复制这些项目的代码或素材。

运行文件与依赖判断参考 [Fabric 文档](https://docs.fabricmc.net/players/installing-fabric/windows) 和 [Modrinth 整合包规范](https://support.modrinth.com/en/articles/8802351-modrinth-modpack-format-mrpack)。CraftBridge 的 ZIP 是独立格式，不是 `.mrpack`；格式说明随包提供，文件可用普通解压软件取出。
